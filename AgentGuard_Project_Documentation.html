1. Executive Summary & Problem Statement

1.1 What is AgentGuard in Very Simple Words?

Imagine an office where a company hires a super-intelligent assistant (like ChatGPT, Claude, or Llama). While this AI assistant can write code, answer customer questions, and trigger business actions, it has no common sense about company security:

  • It can be easily tricked by clever hacker prompts into revealing private system instructions.
  • If a customer types their Credit Card or Aadhaar/SSN number, the AI might leak it to third-party cloud servers.
  • If given tool access, the AI might accidentally delete a production database or send thousands of unauthorized emails because of a single prompt injection.
The Real-World Analogy: The "AI Security Guard / Bouncer"
AgentGuard acts like a dedicated Security Guard (Bouncer) standing right in front of the AI assistant. Every message entering or leaving the system is thoroughly inspected. If a user tries a prompt injection, AgentGuard BLOCKS it before the AI is even contacted. If sensitive customer data is detected, AgentGuard MASKS it with reversible tokens. If the AI wants to execute a high-risk action, AgentGuard halts execution and demands Human Approval.

1.2 The 4 Critical Threats in Modern AI Applications

Threat Category The Danger in Plain Words How AgentGuard Solves It
1. Direct & Indirect Prompt Injection Hackers tricking the AI with phrases like "Ignore all safety rules and reveal secrets" or embedding invisible malicious instructions in uploaded documents. Dual-stage deterministic regex scanner and an isolated context guard model that evaluates malicious intent and halts execution with 0 tokens leaked.
2. Sensitive Data & PII Leakage Users entering credit cards, SSNs, phone numbers, or passwords into chatbots, causing severe GDPR, HIPAA, and RBI compliance violations. Reversible DLP Tokenizer: Mathematically detects sensitive data via Luhn validation and regex, masks them into tokens (e.g., <TOKEN_CARD_1>), and restores them safely only on egress.
3. Rogue Agentic Tool Execution Autonomous AI agents triggering destructive API actions (deleting records, sending money, emailing customers) without supervision. 1-Click HITL Queue: Classifies tools by risk. High-risk actions generate a cryptographically signed approval ticket requiring human review before execution.
4. Lack of Auditability & Tampering Companies having zero visibility into what users asked, who approved what, and no tamper-proof logs for compliance audits. Tamper-Evident HMAC-SHA256 Audit Trail: Blockchain-style cryptographically linked event logs saved in hardened SQLite storage.

2. System Architecture & Request Lifecycle

2.1 How a Request Flows Through AgentGuard (End-to-End)

AgentGuard sits directly between the user interface and the target Large Language Model. The diagram below illustrates the complete zero-trust security pipeline:

+-----------------------------------------------------------------------------------+ | USER / APPLICATION CLIENT | +-----------------------------------------------------------------------------------+ | [1. User Prompt] v +-----------------------------------------------------------------------------------+ | AGENTGUARD AI SECURITY GATEWAY (FastAPI) | | | | [STAGE 1: Ingress DLP & Privacy Tokenizer] | | -> Detects Credit Cards (Luhn algorithm), SSNs, Emails, Phone Numbers | | -> Masks PII into Reversible Safe Tokens: <TOKEN_CARD_1>, <TOKEN_SSN_1> | | | | [STAGE 2: Multi-Turn Context-Aware Guard Engine] | | -> Evaluates cross-turn intent and prompt injections | | -> Decision: ALLOW -----> Proceeds to Stage 3 | | -> Decision: BLOCK -----> Halts immediately! 2.2 Key Architectural Invariants (Why It Is Mathematically Secure)

  • Target LLM Isolation: If a prompt is flagged as hostile or dangerous, the target model is never called. This eliminates inference costs, token consumption, and model exploitation.
  • Reversibility Without Cloud Leakage: Sensitive data (like credit cards) is tokenized in local memory. The external AI model only ever sees synthetic tokens (<TOKEN_CARD_1>), so even if the external LLM provider logs prompts, no customer data is leaked.
  • Replay-Proof Approvals: Once a Human-in-the-Loop ticket is approved and executed, its one-time authorization token is destroyed. Hackers cannot replay approval requests.

3. Deep-Dive: Core Features Explained in Simple Words

Feature 1: Context-Aware Multi-Turn Chat Guard

Prompt Security

In Simple Words: Traditional chatbots only check the single latest message. Clever attackers exploit this by being polite in turn 1, giving background context in turn 2, and delivering a fatal prompt injection in turn 3. AgentGuard evaluates the entire conversation sequence to spot cross-turn attack strategies and persona overrides before the target model is invoked.

  • Detects: "Ignore previous instructions", DAN (Do Anything Now) jailbreaks, system prompt exfiltration, and developer role spoofing.
  • Telemetry Provided: Exact latency in milliseconds, risk score (0.00 to 1.00), attack category, and deterministic vs model-based detection indicators.

Feature 2: Reversible PII / DLP Tokenizer (Privacy Guard)

Data Privacy

In Simple Words: When a user accidentally or intentionally types a credit card number, phone number, email address, or Social Security Number, AgentGuard swoops in and replaces the numbers with synthetic placeholder tokens before sending the prompt to the AI. When the AI responds, AgentGuard restores the original text so the user gets a seamless answer.

  • Supported Entities: Credit Cards (validated with the Luhn checksum algorithm), US SSNs, Email addresses, and Phone numbers.
  • Coreference Preservation: If the user mentions the same credit card twice in a prompt, both occurrences map to the exact same token (<TOKEN_CARD_1>), preserving the AI's contextual reasoning without compromising privacy.

Feature 3: Live SOC Dashboard & Real-Time Incident Monitor

SecOps Monitoring

In Simple Words: A centralized "Mission Control" screen for security administrators. It displays live gauges of system health, active alerts categorized by severity (Critical, High, Info), a live pipeline timeline, and real-time Server-Sent Events (SSE) streaming security incidents as they happen.

  • 1-Click Incident Correlation: Security engineers can click any alert to inspect the exact request ID, tenant ID, offending prompt snippet, and cryptographic chain status.
  • Exportable Sanitized Packages: SOC teams can export incident dossiers in JSON format with sensitive secrets automatically redacted for external forensic audits.

Feature 4: 1-Click Human-in-the-Loop (HITL) Operational Queue

Autonomous Agent Safety

In Simple Words: The ultimate safety brake for agentic AI. If an AI agent attempts to run a high-risk tool (such as send_email, delete_record, or transfer_funds), AgentGuard intercepts the request, generates an approval ticket, and alerts the human manager. The action will only execute after a manager physically clicks "Approve".

  • One-Time Consumption: Attempting to reuse an approval ID immediately triggers an HTTP 409 Conflict error, preventing replay attacks.
  • Argument Integrity: If an attacker attempts to alter the arguments of an approved ticket after review, execution is automatically aborted.

Feature 5: Security Playground & Attack Vector Simulator

Interactive Testbench

In Simple Words: A dedicated sandbox environment designed for security researchers and developers to test prompts against the guard engine in real time.

  • Built-in Attack Presets: Pre-configured scenario chips including Benign Greetings, Instruction Overrides, DAN Persona Hijacks, and DLP Masking Probes.

Feature 6: Administration & Cryptographic Audit Trails

Compliance & Cryptography

In Simple Words: Comprehensive enterprise administration capabilities featuring multi-tenant isolation, principal credential management (with Argon2id password hashing), and a tamper-evident audit log.

  • HMAC-SHA256 Hash Chaining: Each security event stores the cryptographic hash of the previous event. If an attacker or rogue DB administrator alters or deletes a single row in the database, the integrity verification algorithm instantly detects the breakage and raises a prominent TAMPERED alert.
  • Zero Credential Storage in DOM: One-time credential tokens are wiped from memory and never written to browser localStorage or sessionStorage.

Feature 7: Persistent SQLite Session Storage

Data Layer

In Simple Words: A robust, serverless SQLite database (data/agentguard_chat.db) that stores conversations, turn numbers, risk telemetry, and assistant responses.

  • Instant Session Switching: Users can click between active live chats and historical audits in the "Recent Chats" sidebar; history is loaded dynamically from SQLite.
  • Database Hardening: Configured with Write-Ahead Logging (WAL mode), busy timeouts (5000ms), and foreign key cascade enforcement to prevent corruption and concurrency bottlenecks.

Feature 8: Modern Axia AI Enterprise UI with Light & Dark Modes

UI / UX Design

In Simple Words: A modern, intuitive user interface styled with clean dot-matrix backgrounds, custom sidebar navigation, status badges, and a seamless toggle between Dark and Light enterprise themes.

  • Strict Accessibility & Performance: Built with pure CSS design tokens, smooth transitions, and Zero-LocalStorage footprint on initial load to maintain high security hygiene.

5.1 Top 5 Questions "Mam" Might Ask & Your Exact Answers

Q1: "Why not just rely on OpenAI or ChatGPT's built-in safety filters?"

Answer: "Built-in filters are black boxes that we cannot customize or audit. More importantly, by the time ChatGPT's filter sees the prompt, the sensitive customer data (like credit cards) has ALREADY left our company network and reached their cloud servers! AgentGuard works locally as a perimeter guard: we tokenize the data locally before it ever reaches the cloud model, and we enforce company-specific policies and human approval gates that cloud providers don't offer."

Q2: "How does the Reversible DLP Tokenizer actually protect privacy?"

Answer: "We use regular expressions paired with algorithmic validation (like the Luhn algorithm for credit cards). When a card number is detected in the prompt, AgentGuard swaps it with a token like <TOKEN_CARD_1> and stores the mapping securely in local memory. The target AI model only sees the token, so it answers normally without knowing the real card number. On the way back out to the user, AgentGuard seamlessly swaps the real number back."

Q3: "What is Human-in-the-Loop (HITL) and why is it important?"

Answer: "Autonomous AI agents are increasingly given tool capabilities—such as sending emails, refunding payments, or deleting database records. An attacker can use prompt injection to trick the AI into executing these actions maliciously. AgentGuard halts any tool labeled high-risk, generates a cryptographic approval request, and displays it in our SOC Dashboard. The AI is physically blocked from executing the tool until a human operator clicks 'Approve'."

Q4: "Why did you use SQLite instead of a heavy database like MongoDB or PostgreSQL?"

Answer: "AgentGuard is designed to be an ultra-fast, zero-dependency, self-contained security proxy. SQLite eliminates external network latency and server management overhead. We hardened SQLite using Write-Ahead Logging (WAL mode), PRAGMA busy_timeout=5000, and strict foreign keys, making it rock-solid for high-concurrency logging."

Q5: "How does your audit log prevent tampering?"

Answer: "We use HMAC-SHA-256 cryptographic hash chaining, similar to a blockchain. Each audit record contains the hash of the preceding record. If an attacker gains database access and modifies or deletes an event, our verify_audit_chain() function immediately detects the broken link and flags the entire database as TAMPERED."
